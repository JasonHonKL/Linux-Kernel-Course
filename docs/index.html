    文件、inode 与挂载

    Linux 的“文件”不是文件名，而是 inode；目录只是“名字 → inode”的表。理解这一层，`ls -l`、硬链接、挂载、`df` 才不会互相打架。

    阅读 ≈7 分钟 · 检查 ≈5 分钟

    先问两个文件名不同，可能是同一个文件吗？

    可以。硬链接就是多个目录项指向同一个 inode；文件名不是身份，inode 才是。

    用户、passwd 与权限

    登录不是“输入密码然后进 shell”。内核只认 UID/GID；密码哈希、账户状态、PAM 策略都在用户态文件与库里。

    模块 4 · 小节 1

    登录时到底发生了什么

    阅读 ≈7 分钟 · 检查 ≈5 分钟

    先问密码存在 /etc/passwd 还是 /etc/shadow？

    哈希在 /etc/shadow；/etc/passwd 的第二个字段通常只是 x。

    getpwnam() 先查 /etc/passwd 拿 UID/GID/home/shell；认证时再由 PAM 读 shadow 或走 LDAP/SSSD。内核只看到登录后的 UID。

    /etc/passwd 与 /etc/shadow 的字段
    # /etc/passwd
jason:x:1000:1000:Jason:/home/jason:/bin/zsh
#  user  passwd uid  gid  gecos home        shell

# /etc/shadow
jason:$y$j9T$...:19800:0:99999:7:::
#  user  hash     lastchg min max warn inactive expire

    /etc/passwd 必须可读（很多程序查 UID）；/etc/shadow 只有 root 可读。把哈希放回 passwd 是历史遗留，不要这么做。

    预测id 显示的 UID 是谁提供的？

    权限：mode 位 + capabilities

    传统权限是 9 个 mode 位（owner/group/other 的 rwx），加上 setuid/setgid/sticky。现代 Linux 还有 capabilities：把 root 的特权拆成 CAP_NET_ADMIN、CAP_SYS_ADMIN 等。

    sudo 不是“变成 root 的魔法”，而是按 sudoers 规则以另一个 UID 执行命令；它自己也是 setuid 程序 + PAM 策略。

	lock_sock(sk);

	return ret;

    模块 18 · 小节 1

    DRM、GEM/TTM 与 fence

    阅读 ≈10 分钟 · 检查 ≈6 分钟

    先问GPU 命令是谁执行的：CPU 还是 GPU？

    GPU 异步执行。CPU 提交命令、管内存与 fence；完成由中断/轮询回传。

    DRM 把显示与渲染设备抽象成 card/connector/crtc/plane/framebuffer；GEM 管 buffer object，TTM 管显存/GTT 迁移，fence 表示“这一步何时完成”。

    提交、同步、固件、虚拟化

    现代 GPU 还涉及 firmware、power/runtime PM、reset、SR-IOV/虚拟化、display audio。上游驱动可读 drivers/gpu/drm/ 下的 i915、amdgpu、msm、virtio。

    KVM 与 virtio

    虚拟化不是“模拟一台机器”，而是把 CPU、内存、设备访问切成可陷入/可共享的路径。KVM 管 CPU/内存，virtio 管设备。

    模块 19 · 小节 1

    一次 VM exit 与 virtqueue

    阅读 ≈9 分钟 · 检查 ≈6 分钟

    先问VM 里的网卡是“真网卡”吗？

    通常是 virtio 虚拟设备：guest 驱动与 host vhost/设备模型共享 ring，不是直接 passthrough。

    KVM 利用 VT-x/AMD-V 让 guest 直接跑；敏感指令触发 VM exit 回到 host KVM。内存靠 EPT/NPT 二级页表。设备靠 virtio ring 共享。
